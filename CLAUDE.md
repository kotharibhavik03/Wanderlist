# Wanderlist

Kotlin Multiplatform + Compose Multiplatform travel app (Android + iOS from one codebase). Despite the parent folder name, this is **not** Flutter.

- Compile both targets after every change before handing it over. Runtime behaviour is confirmed by me on device.

## Stack
- Package `com.rizz.wanderlist`. Modules: `androidApp/`, `shared/`, `iosApp/`. Screens live under `views.*`; the theme is `com.rizz.wanderlist.views.theme`.
- Versions are in `gradle/libs.versions.toml` (source of truth). Key ones: Kotlin 2.4.20, Compose Multiplatform 1.12.2, AGP 9.1.1 (built-in Kotlin), Material3 1.12.0-alpha03, Navigation 3 1.2.0-rc01, lifecycle 2.11.0, compileSdk 37, minSdk 24, iOS 16+.
- Koin 4.2.2, coroutines 1.11.0, serialization 1.11.0. Material icons extended is available.
- Navigation 3: sealed `Route : NavKey`. **Every route must be registered** in the polymorphic `SavedStateConfiguration` in `AppNavigation.kt` (required on iOS).
- KMPAuth 3.0.6 (wraps GitLive firebase-kotlin-sdk 3.0.0-alpha01; fallback KMPAuth 3.0.4 with GitLive 2.4.0).
- iOS via SPM: firebase-ios-sdk "Up to Next Major from 12.17.0" (Firebase 13 conflicts with GoogleSignIn 10), GoogleSignIn-iOS 10.0.0.

## Repo hygiene
- Firebase config files are **not in Git**: `androidApp/google-services.json` and `iosApp/GoogleService-Info.plist` (ignored by `**/GoogleService-Info.plist`). Never commit them or any API key (the Maps key included).
- `.swiftpm-locks/` is generated by the Kotlin SwiftPM import. Commit `swiftImport/` (it holds `Package.resolved`, the iOS dependency lockfile); never commit `swiftPMCheckout/` (a ~1.2 GB cache).
- `iosApp/KotlinMultiplatformLinkedPackage/` is generated but tracked, because the Xcode project references it.

## Architecture
- Clean Architecture: `domain` (models, repository interfaces, use cases), `data` (implementations), `views` (UI).
- MVVM: immutable `StateFlow` UI state, a stateful `Route` composable (gets the ViewModel) over a stateless `Screen`.
- One-shot events through `Channel`. Errors that must survive rotation live in state.
- Use cases only where there is logic. They return `Result` and never swallow `CancellationException`.
- Visibility and security rules belong in the repository / backend, not in screens.
- Koin wiring is in `di/AppModule.kt`; Koin and KMPAuth start from `initApp()` (Android `WanderlistApp`, iOS `MainViewController`).
- `AddPlaceViewModel` is host-scoped in `AppNavigation` (shared by Add Place and Map Picker). The shared `goBack` clears the draft when leaving Add Place; the draft is also cleared on sign-out.

## Product requirements (final)
- Google login (done) and change profile image.
- **Collections** (e.g. "Goa trip", "Visited") with one emoji icon and multiple colours. A collection holds multiple places.
- **Places**: name, notes, coordinates, address, visit date, rating, Wishlist/Visited status. Category and cost are **deliberately deferred**.
- **Photos** per place (optional, multiple). Each photo can be marked private (visible only to its uploader). Each collection has an "All photos" view.
- **Map**: Google Maps, saved places as markers. Marker defaults to the collection's icon and colour, or the user picks an icon or one of the place's **shared** photos. A private photo may never be a marker.
- **Collaboration**: add people by Google email as **Collaborator** (edit the place, add photos) or **Visited with** (view the place, add their own photos). No acceptance step. The invitee sees only that place, under "Shared with me", never the collection. Invites for emails not yet signed up are stored and appear on first sign-in. A member can leave a place; their photos on it go with them.
- **Directions**: open Google Maps / Apple Maps to the place.
- Follow/unfollow is **out of scope**.
- Cost: Google Maps + Firebase Storage on Blaze (budget alert ~₹100). Photos compressed to ~1600px JPEG at 80%. Keep a `PhotoStorage` interface so the provider is swappable. Avoid paid Maps features (Places, Directions API, Street View).

## Defaults assumed (can change)
- Place search by pin-drop plus free platform geocoders (Android `Geocoder`, iOS `CLGeocoder`), not paid Google Places.
- One "Notes" field (description and notes merged).
- Photos shared by default, with a lock toggle for private.
- "Shared with me" is a segment on the Collections tab.
